    Supported models and configuration

    Infinity v3 serves dense, sparse and token-vector embeddings, reranking, classification, and structured decisions with the native LibTorch backend. Choose a checkpoint below by task. The architecture coverage explains the underlying model paths and their limitations.

    These docs track main. Use an image containing the model integration you need; older alpha images may lack support. Listing a checkpoint describes its supported task, not an accuracy or throughput guarantee for every precision and GPU. The support-basis column identifies the implemented architecture and task head or pooling used by each checkpoint. Related checkpoints are included when their published configuration matches that path; sharing a training organization does not by itself establish support. Checkpoint-specific execution and architecture fixture coverage are different levels of validation.

    Common launch configuration

    Use a published NVIDIA image from the container registry. The example uses nvidia-latest; pin its version or digest for reproducible deployments. CUDA requires an Ampere/SM80 or newer GPU and NVIDIA Container Toolkit.

    docker run --rm --gpus all -p 8000:8000 -v infinity-cache:/data \
  ghcr.io/michaelfeil/infinity_v3:nvidia-latest \
  --model-id BAAI/bge-small-en-v1.5 \
  --torch-device cuda --dtype bfloat16 \
  --max-batch-tokens 8192 \
  --hostname 0.0.0.0 --port 8000

    Replace --model-id and the task settings with a table row below. The native image selects LibTorch automatically. For a locally installed binary, pass the same flags to infinity_v3. Tables use BF16 compute unless a row specifies a different --dtype; replace the common dtype flag in that case. Checkpoint storage precision does not set compute precision. For CPU, use a LibTorch CPU build, --torch-device cpu and --dtype float32.

    --max-batch-tokens is the total batch capacity, not a model's context length or a memory guarantee. These are starting configurations: lower the budget for smaller GPUs and leave room for activations, media tokens and warmup. --max-sequence-length can impose a separate per-input cap. Automatic text truncation is enabled by default; use --auto-truncate=false to reject oversized text inputs instead. Some tasks and media inputs reject oversized inputs regardless of this setting. Disable truncation when dropping text would change the intended result. See sequence and batch limits.

    Use --revision to pin a Hugging Face checkpoint, or pass a local directory containing its weights, tokenizer, pooling/head configuration and task sidecars. Gated checkpoints also require access credentials. A base language model needs a trained retrieval or classification head to provide that task's intended scores.

    All visible CUDA GPUs are used by default. Each GPU loads a full replica, including every MoE expert. To select only two or four visible GPUs, add --backend-device-ids 0,1 or --backend-device-ids 0,1,2,3. Every selected GPU must fit the full model; this does not shard weights. Wait for /health before sending traffic; model warmup is part of startup.

    Dense text embeddings

    Use /v1/embeddings with input strings. Pooling is read from the checkpoint metadata automatically; the examples omit redundant overrides. Keep the saved 1_Pooling/config.json when copying a checkpoint to a local directory. Explicit --pooling splade selects the sparse task described below.

    For Nomic v1.5, prefix retrieval queries with search_query: and documents with search_document:. It returns 768 dimensions by default. Qwen3 queries use the checkpoint's instruction format (Instruct: ...\nQuery: ...); documents use their ordinary text. E5 v2 and non-instruct multilingual E5 use query: and passage: prefixes, including for non-English text. E5-Mistral, multilingual E5 large instruct and GTE-Qwen2 use their model-card instruction/query formats. Jina code models distinguish code and text retrieval tasks through their trained prompts. Nomic v1 uses the same task-prefix convention as v1.5. GTE, BGE, Snowflake and Mixedbread also have model-specific retrieval instructions: follow the linked model card consistently when building and querying an index. A saved prompt_name can select a checkpoint prompt; do not also insert the same prefix manually.

    Perplexity Embed v1 supports floating-point output only; contextual variants are unsupported. BGE-M3 here provides dense embeddings. Nemotron Embed 3 supports text; 3.5 additionally supports document images. Use their query/document instructions and checkpoint formatting; they are separate from Nemotron ColEmbed.

    Late-interaction embeddings

    Use /v1/embeddings to receive a matrix of token vectors per input, then score with MaxSim in your retrieval system. Do not force sentence pooling, request a dimension override, or use single-vector /similarity scoring. ColQwen3 additionally accepts images. It needs the trained query suffix of ten <|endoftext|> tokens; image documents use a user image message with Describe the image. and no assistant prefix.

    ColBERT does not automatically add query/document markers or expand queries. Use the checkpoint's exact input formatting; final token IDs can express that formatting directly. Native NVIDIA Nemotron ColEmbed V2 4B/8B is also supported with normalized text/image token vectors and its checkpoint retrieval instructions; the separate 3B Eagle architecture is outside this path. See matrix formats and model-specific requirements.

    Token classification and NER

    Use /predict_tokens with inputs, rather than /v1/embeddings. Label names come from the checkpoint's id2label. aggregation_strategy: "simple" groups tokens into spans; choose a strategy appropriate for the checkpoint's labeling scheme. PII detection and medical NER have different label sets and training domains. The BERT CoNLL and English RoBERTa models cover general entities; Davlan and WikiNEuRal provide multilingual entities, CamemBERT covers French, and the clinical/de-identification models have domain-specific labels. DeBERTa-v2/v3 execution remains experimental. Training on clinical text does not imply coverage of every medical concept or de-identification policy.

    Text classification and reward scoring

    Use /v1/classify. Skywork scores a user/assistant conversation; send native messages and use_activation: false to obtain a raw reward score. Applying softmax to a single-label head would return 1.0 instead of a useful reward. FinBERT provides financial-sentiment labels; CardiffNLP provides its saved social-text sentiment labels. Use input for those sequence classifiers and retain their checkpoint label mapping. Preprocess mentions, URLs and other text as required by the corresponding model card. Other supported encoder/decoder classification checkpoints need a saved trained head and matching label configuration; architecture support alone does not supply labels or turn an embedding model into a classifier.

    Typed decisions

    Use /v1/systemone and retain the checkpoint's trained heads and protocol sidecars. Set the protocol explicitly as shown; Laya is detected from its rl_agent_config.json and needs no decoder protocol flag. A local path or custom served model name does not select a protocol by its name. The d3, d3-mini, pplx-decider-v1.1-27b and pplx-decider-flash-v1.2 short aliases select their registered checkpoints and protocols automatically.

    The protocol determines supported question types, media and request semantics; do not assume every model accepts the same payload. Laya accepts text/JSON state and rejects native message conversations. OneJev supports image inputs when the vision tower is present; Perplexity Flash v1.2 supports shared text/images and calibrated joint readouts. See decision inputs, OneJev configuration, and the running server's /docs for the selected protocol.

    Request examples

    Run the corresponding model first. The model field is optional with one loaded model; if provided, it must match its ID or configured --served-model-name.

    Dense embedding request

    curl http://localhost:8000/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"BAAI/bge-small-en-v1.5","input":["A document about semantic search."],"encoding_format":"float"}'

    Multimodal request

    After starting Qwen/Qwen3-VL-Embedding-2B, send a user conversation. Replace <base64 PNG> with an actual base64-encoded PNG (without the angle brackets). Inline media avoids configuring a remote-image host allowlist.

    {
  "model": "Qwen/Qwen3-VL-Embedding-2B",
  "input": [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,<base64 PNG>"}},
    {"type": "text", "text": "Represent this image for retrieval."}
  ]}],
  "encoding_format": "float"
}

    Post this JSON to /v1/embeddings. Use the checkpoint's trained retrieval prompt for production queries and documents. Audio/video support is model-specific; Qwen3-VL's image path does not imply support for those modalities.

    Reranking request

    curl http://localhost:8000/rerank \
  -H 'Content-Type: application/json' \
  -d '{"model":"BAAI/bge-reranker-base","query":"What is semantic search?","texts":["Retrieval by meaning.","A cake recipe."],"raw_scores":true}'

    The response ranks the supplied documents. Raw logits are relevance scores, not calibrated probabilities.

    Token classification request

    curl http://localhost:8000/predict_tokens \
  -H 'Content-Type: application/json' \
  -d '{"model":"gravitee-io/bert-small-pii-detection","inputs":["Contact Jane Smith in San Francisco."],"aggregation_strategy":"simple"}'

    The response reports predicted labels, scores and spans according to the checkpoint and aggregation strategy.

    Reward scoring request

    curl http://localhost:8000/v1/classify \
  -H 'Content-Type: application/json' \
  -d '{"model":"Skywork/Skywork-Reward-V2-Qwen3-0.6B","messages":[{"role":"user","content":"Why is the sky blue?"},{"role":"assistant","content":"Air molecules scatter shorter blue wavelengths more strongly."}],"use_activation":false}'

    Sentiment classification request

    After starting ProsusAI/finbert, send strings to the sequence classifier:

    curl http://localhost:8000/v1/classify \
  -H 'Content-Type: application/json' \
  -d '{"model":"ProsusAI/finbert","input":["The company reported stronger earnings."]}'

    Class scores use the checkpoint's positive, negative and neutral labels. They are separate from Skywork's raw reward scores.

  -H 'Content-Type: application/json' \
  -d '{"model":"naver/splade-cocondenser-ensembledistil","inputs":["A document about semantic search."]}'

    D3-mini decision request

    curl http://localhost:8000/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{"model":"vllm-sr/d3-mini","state":"The parcel arrived damaged. Please send a replacement.","questions":{"route":{"type":"choice","instructions":"Which team should handle this request?","criteria":{"returns":"Damaged items and replacements","billing":"Payments and invoices"}}}}'

    This returns a typed decision for route. Use the running schema for other protocols and question types. D3-mini can also process supported image state; text-only examples do not require a media configuration.

    Similar models that need additional integration

    A familiar organization name or Hugging Face task tag is insufficient to select a native implementation. These examples are excluded from the supported model tables above:

    Model or family Missing native integration
    jinaai/jina-embeddings-v3 Custom XLM-RoBERTa Flash rotary encoder and task-specific LoRA adapters; ordinary XLM-RoBERTa support does not cover this contract.
    jinaai/jina-reranker-v2-base-multilingual Custom XLM-RoBERTa Flash configuration/loader; this checkpoint does not declare a standard native model_type.
    Jina reranker v1 tiny/turbo Checkpoints declare JinaBertModel rather than a native sequence-classification architecture; their reranker head/loading contract needs integration.
    cross-encoder/ms-marco-electra-base ELECTRA backbone and classifier support.
    GLiNER Span/label-conditioned extraction architecture and API, rather than a fixed token-label head.
    numind/NuNER-v2.0 Publishes a RoBERTa representation encoder rather than a ready-to-serve ForTokenClassification head.

    Architecture support beyond this catalog

    The model list is not exhaustive. Compatible checkpoints also use native RoBERTa, XLM-RoBERTa, CamemBERT, DistilBERT, Nomic BERT/MoE, JinaCode, Llama, Mistral/Ministral3, Qwen2, Qwen3/MoE, Qwen3.5 dense/MoE, Gemma3 text, Gemma4 and experimental DeBERTa-v2/v3 paths. Support depends on architecture, trained output head, tokenizer and media metadata. Instruction checkpoints can expose hidden-state embeddings without being trained retrieval models. Consult native model coverage before substituting a checkpoint; arbitrary remote custom code is not executed to add a new architecture.
