    Embedding formats and client usage

    Choose the response format that fits your application: JSON arrays for easy integration, or packed tensors for NumPy views without a per-element conversion. Requests remain JSON in every case.

    Choose a format

    encoding_format Best for Response
    float (default) Standard OpenAI-compatible clients JSON arrays of numbers
    base64 Clients that decode packed vectors Base64-encoded vectors
    tensor NumPy and variable-length token embeddings A buffer with explicit shape and dtype

    The tensor format is available in Infinity v3 on /embeddings, /v1/embeddings, /embed and /embed_all. It does not change pooling, normalization or truncation. Include model when serving multiple models.

    Python: Baseten Performance Client

    For batched embedding workloads, use baseten-performance-client. Its Rust implementation handles concurrent requests and exposes results as NumPy arrays. It works with a local Infinity server as well as hosted endpoints.

    pip install baseten-performance-client numpy

    from baseten_performance_client import PerformanceClient, RequestProcessingPreference

client = PerformanceClient(
    base_url="http://localhost:8000",
    api_key="unused",  # For a local server without authentication; otherwise use its API key.
)
response = client.embed(
    input=["A mountain lake.", "An alpine lake."],
    model="sentence-transformers/all-MiniLM-L6-v2",
    encoding_format="float",
    preference=RequestProcessingPreference(batch_size=32, max_concurrent_requests=8),
)
embeddings = response.numpy()  # shape: [inputs, dimensions]

    Version 0.1.16 assembles the vectors into a contiguous array in Rust; .numpy() is not a zero-copy view of the response bytes. For that, use v3's tensor format and np.frombuffer as below. The client's typed embedding response does not yet support this tensor envelope.

    Zero-copy NumPy views

    Request tensors with MessagePack to receive binary buffers directly, without base64 decoding. np.frombuffer views a buffer as float32 values; reshape restores its dimensions without copying the values.

    pip install requests msgpack numpy

    import msgpack
import numpy as np
import requests

response = requests.post(
    "http://localhost:8000/v1/embeddings",
    headers={"Accept": "application/msgpack"},
    json={"input": ["A mountain lake."], "encoding_format": "tensor"},
)
response.raise_for_status()
tensor = msgpack.unpackb(response.content, raw=False)["data"][0]["embedding"]
embedding = np.frombuffer(tensor["data"], dtype="<f4").reshape(tensor["shape"])

print(embedding.shape)          # (dimensions,)
print(embedding.flags.owndata)  # False: NumPy shares the decoded binary buffer

    Zero-copy here means from the decoded buffer to NumPy. HTTP reception and MessagePack decoding still allocate memory. The view is read-only when backed by immutable bytes; use embedding.copy() when you need to modify it.

    For JSON responses, omit the Accept header and decode the base64 buffer first:

    import base64

response = requests.post(
    "http://localhost:8000/v1/embeddings",
    json={"input": ["A mountain lake."], "encoding_format": "tensor"},
)
response.raise_for_status()
tensor = response.json()["data"][0]["embedding"]
buffer = base64.b64decode(tensor["data"])
embedding = np.frombuffer(buffer, dtype="<f4").reshape(tensor["shape"])

    Base64 decoding allocates a buffer; the resulting NumPy view shares that buffer.

    Token embeddings

    Use /embed_all with {"inputs": ["hello"], "encoding_format": "tensor"} for supported token-embedding models. The response is a top-level list of tensors, each shaped [tokens, dimensions]. Decode each input independently using the same np.frombuffer(...).reshape(...) pattern. Token counts can differ, so no batch padding is added. Stacking separate buffers into one array requires a copy.

    Tensor wire format

    Each tensor has shape, dtype: "float32", data_encoding and data. Buffers are contiguous, row-major, little-endian IEEE 754 float32, with exactly 4 * product(shape) bytes and no header or padding. Int8 tensors are not supported.

    JSON uses data_encoding: "base64" and a string; MessagePack uses data_encoding: "binary" and bin data. Both application/msgpack and application/x-msgpack are accepted.

    Pooled vectors have shape [dimensions]; token matrices have shape [tokens, dimensions], preserving returned token order. Empty matrices use [0, 0]. OpenAI-style endpoints place tensors in data[i].embedding; /embed and /embed_all return a list of tensors. This tensor option is v3-specific.
